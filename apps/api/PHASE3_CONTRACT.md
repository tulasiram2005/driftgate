# Phase 3 API contract

All project routes require Bearer authentication and project membership; writes require ADMIN or QA.

- POST `/api/v1/projects/:projectId/automated-runs`: required `Idempotency-Key` header (1..128 ASCII letters/digits/underscore/hyphen); body `{environment:"STAGING"|"UAT"|"PREPROD"|"PROD", checks?:["catalogue","product","cart"], matrix:[{browser:"chromium"|"firefox"|"webkit",device:"desktop"|"mobile"}], dispatch?:"LOCAL"|"GITHUB", retries?:0|1|2, suiteId?:string}`. Checks default to all three, dispatch LOCAL, retries 1. Fixed runner checks are independent of managed test cases. Optional suite is checked for project ownership. Returns `{data:run}` with results (one per check/matrix cell), status and persisted dispatch. Same key/body returns same run; changed body returns 409. GET same collection lists automated runs with `{data:run[],nextCursor}`.
- GET `/api/v1/projects/:projectId/runs/:runId`: `{data:run}` including results, attempts and evidence.
- GET `/api/v1/projects/:projectId/runs/:runId/events`: authenticated SSE, `Last-Event-ID` numeric persisted event cursor. Events `run`, JSON data, heartbeat comments. Reconnect with Authorization using fetch streaming.
- POST `/api/v1/runner/callback`: exact v1 envelope in `apps/runner/CONTRACT.md`, `X-Runner-Timestamp` Unix seconds and `X-Runner-Signature: sha256=<hex HMAC SHA256(timestamp.rawBody)>`. Shared RUNNER_CALLBACK_SECRET. +/-300s window. Event IDs persist in PostgreSQL. Identical redeliveries return 200 and do not emit duplicate events; changed replay returns 409.
- POST `/api/v1/projects/:projectId/runs/:runId/results/:resultId/evidence`: manual screenshot upload reservation `{contentType:"image/png"|"image/jpeg",sizeBytes}` returns `{data:{evidence,uploadUrl}}`; PUT bytes to uploadUrl then POST same path + `/:evidenceId/complete`.
- GET same evidence path + `/:evidenceId/url`: returns `{data:{url,expiresIn:300}}` after project and object ownership checks.

Existing manual run endpoints remain compatible. Automated result cells carry `browser`, `device`, `attempts`, `evidence`, `flaky`. Queue dispatch is durable via transactional outbox. API dependency additions require parent workspace install; root lockfile untouched.

Run fields: `id, projectId, suiteId` (nullable), `environment, browser, device, createdAt, mode` (AUTOMATED/MANUAL), `status` (QUEUED/RUNNING/PASS/FAIL/FLAKY/TIMED_OUT; old manual PENDING), `dispatch` (LOCAL/GITHUB), `results`. A cell has `id,runId,caseId` (fixed checkId for automation), `title,version,steps,status` (NOT_RUN/PASS/FAIL), `notes,browser,device,flaky,attempts,evidence`. Attempts: `id,resultId,number,status,durationMs,error,createdAt`. Evidence: `id,resultId,key,kind,contentType,sizeBytes,ready,createdAt`. SSE event data `{status}` or `{resultId,status,flaky}`; fetch detail after event for full evidence/attempts. SSE `id` is numeric; event name `run`. Internal request hash/idempotency key and dispatch payload are omitted from public responses.
